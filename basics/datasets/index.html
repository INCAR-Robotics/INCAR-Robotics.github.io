    Creating Datasets

    Dataset Structure.

    A dataset has the following structure:

    example_ds/
├── demo_0/
│   ├── example_feature/
│   │   └── data.h5
│   ├── video_feature/
│   │   ├── data.mp4
│   │   └── timestamps.h5
│   └── meta.json
├── demo_1/
│   └── ...
├── demo_2/
│   └── ...
└── dataset_config.json

    A demo is one recording consisting of various features. Features can be an of one of the following types:

    • "VISUAL": these are image types
    • "STATE": these are arrays of floats that can be read from the robot system (e.g. joint states, force sensors)
    • "ACTION": these are arrays of floats that are input into the robot system (e.g. a cartesian velocity command)
    • "TEXT": this can be used for serializing any other data, e.g. user input button data can be saved as a json string.

    Each dataset has a config file named dataset_config.json which describes the features and their shapes that are present in the dataset. Furthermore each demo has a meta.json file which describes when the demo was recorded, statistics used for normalization as well as some other information.

    Creating a dataset

    You can create a dataset by manually creating a folder with a dataset_config.json, or directly from the GUI. An example of the dataset_config.json file can be found below:

    {
    "version": "0.0.1",
    "video_fps": 30,
    "features": {
        "video_left": {
            "type": "VISUAL",
            "shape": [3, 480, 640]
        },
        "teleop_action_left": {
            "type": "ACTION",
            "shape": [7]
        },
        "robot_state_left": {
            "type": "STATE",
            "shape": [7]
        },
        "buttons_left": {
            "type": "TEXT",
            "shape": []
        }
    }
}

    Recording a dataset

    There are two ways of recording a dataset:

    • Using the buttons in the GUI
    • Using button combinations on the Quest controllers: Y + right trigger to start and stop recording.
      • Discarding a recording is done with B + right trigger

    Warning

    Make sure that a dataset is selected prior to recording, in order for the recording to be saved.

    The recording will include a couple seconds before the start of a recording, and about half a second after the end of a recording if this data is available.

    In order to reduce the storage space, video features should be compressed into a mp4 file, instead of raw RGB values. After a recording session, you can run the following command to compress any newly recorded demos to mp4:

    cd core/scripts
python 02_process_after_record.py [relative_path_to_dataset]

    Which features are recorded?

    There are some features which are always recorded:

    • "teleop_action_left": {"type": "ACTION", "shape": [7]}, This is the teleop_action as received from the teleoperation app, with x, y, z, rx, ry, rz, gripper commands from the left controller
    • "teleop_action_right": {"type": "ACTION", "shape": [7]}, This is the teleop_action as received from the teleoperation app, with x, y, z, rx, ry, rz, gripper commands from the right controller
    • "buttons_left": {"type": "TEXT", "shape": []}, The json string for all buttons of the left teleop controller
    • "buttons_right": {"type": "TEXT", "shape": []}, The json string for all buttons of the right teleop controller

    Then, there are the robot states which are recorded for each robot that is sending out state on the robot state channel (more information here). The shape should match the size of the robot state that you are sending out.

    • "robot_state_{ROBOT_ID}": {"type": "STATE", "shape": [...]},

    Each incoming video stream is recorded under with as key the video stream ID

    Finally, each datachannel is recorded under the label of the datachannel. The data will be attempted to be parsed to a np.ndarray.

    Recording failure cases

    A couple failure cases exist and will be printed to the terminal in case they are found. Note that no data is recorded in the case of a failure:

    1. Not all features as established in dataset_config.json are received. Make sure that all features you want to record are actually recorded as described here. Also make sure there are no typos, and that the robot is actually sending out the data.

    2. The feature type established in dataset_config.json differs from the received type

    3. The shape if the received data does not correspond to the shape established in dataset_config.json
